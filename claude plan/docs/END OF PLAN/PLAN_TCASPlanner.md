```swift

var universityName: String
var notes: String
var createdAt: Date

// ลบทิ้ง
❌ @Relationship ... var checklist: [TCASChecklistItem]

@Relationship(deleteRule: .cascade, inverse: \TCASScoreWeight.entry)
```

### 2.2 `TCASScoreWeight` — ใหม่
น้ำหนัก % ของ 1 วิชา ในคณะ 1 อัน · **ผู้ใช้กรอกเองจากระเบียบการ**
```swift
var examCode: String          // "TGAT1" · "TPAT3" · "A61"
var percent: Double           // น้ำหนักรายวิชาที่ใช้คำนวณจริง (เสมอ)
var groupName: String = ""    // "" = โหมดรายวิชา · มีค่า = อยู่ในกลุ่ม
var groupPercent: Double = 0  // น้ำหนักของทั้งกลุ่ม (เก็บซ้ำทุกแถวในกลุ่ม)
var entry: TCASEntry?
```

**การตัดสินใจที่ผมเลือกเอง (ไม่ได้ถาม Few):** ไม่สร้าง model `TCASWeightGroup` แยก
เก็บ `groupName`/`groupPercent` ซ้ำในทุกแถวของกลุ่มแทน
- **ข้อดี:** ลด @Model จาก 4 เหลือ 3 · relationship ซ้อนน้อยลง = เสี่ยง migration น้อยลง
- **ข้อเสีย:** แก้ % ของกลุ่มต้องเขียนทุกแถวพร้อมกัน
- **กันพลาด:** ให้ `TCASScoreEngine.setGroupPercent(...)` เป็น **จุดเดียว**ที่แก้ค่ากลุ่ม ห้าม View เขียนตรง

## 4. ระบบคิดคะแนนย้อนกลับ

### 4.1 สูตร — `Core/TCAS/TCASScoreEngine.swift` (ใหม่, logic ล้วน)
```
คะแนนรวม = Σ (คะแนนดิบ ÷ คะแนนเต็ม × 100) × น้ำหนัก%
```
จุดที่คนพลาด: **คะแนนเต็มไม่เท่ากัน** (TPAT 300 · A-Level 100) ต้องแปลงเป็นสัดส่วนก่อนถ่วงน้ำหนัก

```
totalPercent(entry)           → รวม % ครบ 100 มั้ย (ไม่ครบ = เตือน ไม่บล็อก)
currentScore(entry, records)  → คะแนนรวมปัจจุบัน
ceilingScore(entry, records)  → เพดานถ้าที่เหลือได้เต็ม
gap(entry)                    → เป้า − ปัจจุบัน (nil ถ้าไม่ได้ตั้งเป้า)
leverage(entry, records)      → เรียงวิชาตาม 100 × น้ำหนัก ÷ คะแนนเต็ม
headroom(entry, records)      → (เต็ม − ที่ได้) × leverage
requiredAverage(entry,records)→ โหมดล็อก §4.3
setGroupPercent(...)          → จุดเดียวที่แก้ % ของกลุ่ม (§2.2)
```

### 4.2 Leverage — จุดขายหลัก
นักเรียนเห็น "TPAT3 = 30%" ก็คิดว่าต้องทุ่ม TPAT3 **ซึ่งผิด**
```
A-Level คณิต1  25% ÷ 100 → 0.250   ← คุ้มสุด
A-Level ฟิสิกส์ 15% ÷ 100 → 0.150
TPAT3          30% ÷ 300 → 0.100
TGAT1          20% ÷ 100 → 0.200
```
UI แสดง **leverage คู่กับ headroom เสมอ** — เพราะวิชาที่ leverage ดีแต่ได้คะแนนสูงแล้วเหลือให้ดันน้อย
ให้ผู้ใช้ตัดสินเอง ไม่ชี้นิ้วว่า "จงอ่านวิชานี้"

### 4.3 โหมดล็อก — "สอบไปแล้ว"
ผู้ใช้ **ติ๊กเอง**ว่าวิชาไหนสอบแล้ว (`hasTaken`) → แอปคำนวณว่าที่เหลือต้องได้เฉลี่ยเท่าไร
```
ล็อกแล้ว (TGAT + TPAT3)   = 25.50
เป้าหมาย                  = 62.00
ที่เหลือต้องช่วยอีก        = 36.50
น้ำหนักรวมที่ยังไม่สอบ     = 50%
→ ต้องได้เฉลี่ย 73.0% ในวิชาที่เหลือ
```
⚠️ **ถ้าคำนวณได้เกิน 100%** = ต่อให้ได้เต็มก็ไม่ถึงเป้า → **ห้ามแสดงเป็นตัวแดงว่า "เป็นไปไม่ได้"**
ใช้ `Theme.Colors.warning` + ข้อความว่า *"ถึงได้เต็มทุกวิชาก็ยังไม่ถึงเป้าที่ตั้งไว้ ลองปรับเป้าหมาย หรือดูคณะอันดับรองที่บันทึกไว้"*
(ควรให้สกิล `design:ux-copy` เกลาก่อนใช้จริง)

### 4.4 กรณีขอบ
| กรณี | ทำยังไง |
|---|---|
| น้ำหนักรวมไม่ครบ 100% | เตือน **ไม่บล็อก** — บางคณะมีสัมภาษณ์/แฟ้มสะสมงานถ่วงด้วย |
| ไม่ได้ตั้งเป้า (`targetScore == 0`) | ซ่อน gap และโหมดย้อนกลับ · แสดงแค่คะแนนรวม + leverage |
| ยังไม่บันทึกคะแนนบางวิชา | นับเป็น "ยังไม่ระบุ" **ห้ามนับเป็น 0** → แสดงเป็นช่วง "52.65 – 100.0 (ปัจจุบัน – เพดาน)" |
| กสพท | ไม่ต้อง special case — เป็นชุดน้ำหนักที่ผู้ใช้กรอกเหมือนกัน (TPAT1 30% + A-Level 70%) |

### 4.5 Unit test — จุดแรกของโปรเจกต์ที่ test ได้จริง
`TCASScoreEngine` เป็น struct + static func ล้วน ไม่มี I/O

## 5. ระบบเขียน SOP

### 5.1 กติกา
- **1 ฉบับ ต่อ 1 คณะ**
- ผู้ใช้เลือกโหมดตอนเริ่ม: **ก้อนเดียว** หรือ **6 ช่องตามโครงสร้าง**
- โหมด 6 ช่อง → กด "รวมเป็นฉบับเดียว" → **alert เตือนก่อน** → รวมแล้ว `isMerged = true`
- **รวมแล้วกลับไปแก้ทีละส่วนไม่ได้อีก** ข้อความ 6 ช่องเดิมหายไป → alert ต้องบอกตรงๆ
- ข้อความที่รวม: **ไม่มีหัวข้อกำกับ เรียงความล้วน** 6 ส่วนกลายเป็น 6 ย่อหน้า คั่นด้วย `\n\n` (ข้ามช่องที่ว่าง)
- **ไม่มีเทมเพลตโครงเปล่า** (Few ตัดออกแล้ว)

### 5.2 ชื่อ 6 ส่วน — ภาษาไทยล้วน
```
1. บทนำ                  ← Introduction
2. พื้นฐานการศึกษา        ← Academic Background
3. ผลงานและประสบการณ์     ← Projects / Experience
4. ทำไมต้องที่นี่          ← Why This University
5. เป้าหมายในอนาคต        ← Future Goals
6. บทสรุป                ← Conclusion
```

### 5.3 การบันทึก
- **ปุ่ม "บันทึก"** มุมขวาบน
- **กันลืมตอนออก:** ถ้ามีข้อความเปลี่ยนแล้วยังไม่บันทึก → `.confirmationDialog` "ยังไม่ได้บันทึก" → [บันทึกแล้วออก · ออกโดยไม่บันทึก · ยกเลิก]

### 5.4 ที่เหลือในหน้า
- **นับตัวอักษร** แสดงเฉยๆ มุมล่าง ไม่มีขีดจำกัด ไม่เตือน (ภาษาไทยนับคำยาก — นับตัวอักษรแม่นกว่า)
- **ปุ่มคัดลอกทั้งฉบับ** → `UIPasteboard` + toast "คัดลอกแล้ว"

## 9. จุดที่ผมตัดสินใจเอง — ทักท้วงได้

1. **§7 "คะแนนสอบของฉัน" เป็น Section บนสุดของหน้าลิสต์คณะ** — Few ยังไม่ได้ระบุทางเข้า
   ผมเลือกจุดนี้เพราะคะแนนใช้ร่วมทุกคณะ จึงควรอยู่ระดับเดียวกับลิสต์ ไม่ใช่ซ่อนในคณะใดคณะหนึ่ง
2. **§2.2 ไม่แยก model `TCASWeightGroup`** — เหตุผลและ trade-off เขียนไว้แล้ว
3. **§2.1 `sopStore` เป็น array แทน optional relationship**
4. **§7 การ์ดคะแนนแสดง:** คะแนนรวม (ช่วง ปัจจุบัน–เพดาน) · gap ถ้าตั้งเป้าไว้ · leverage 3 อันดับแรก
   · ผลโหมดล็อกถ้าติ๊กว่าสอบแล้วอย่างน้อย 1 วิชา
5. **§5.4 นับตัวอักษรไม่ใช่คำ** — ภาษาไทยไม่เว้นวรรคระหว่างคำ นับคำได้ไม่แม่น
