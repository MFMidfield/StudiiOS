### 1.1 หลักการที่ยึดไว้ — อย่าให้หลุดตอนแก้รอบต่อไป

> **ซ่อมสิ่งที่พิสูจน์ได้ · ติดธงสิ่งที่พิสูจน์ไม่ได้** — ห้ามตั้งเป้าอัตโนมัติ 100%

- **ห้าม hardcode ว่าวันเป็นแถว** — ตรวจ orientation ทุกครั้ง
- **ห้ามใช้ชื่อวันเป็น anchor หลัก** — Vision อ่าน "พุธ" ไม่ออกในใบแรก
- **ห้ามใช้ `confidence` เลือก candidate** — วัดแล้วสัญญาณกลับด้าน (`PLAN_OCRAccuracy.md` §0.2)
- **ห้ามใช้ offset คงที่จำแนก sub-row** — ใช้ไวยากรณ์ของแต่ละฟิลด์แทน

### 1.2 ที่ทำต่างจากแผนเดิม (ยังคงไว้)

| จุด | แผนเดิม | ที่ทำจริง + เหตุผล |
|---|---|---|
| **โหวตข้ามภาพ** | เสียงข้างมากบน tail | **เอกฉันท์** — tail `32101` ในใบ ม.5/9 ใช้ร่วมกัน 6 วิชา (ท ค พ อ ศ ส) · majority จะเขียนทับของถูก 6 ช่องเพื่อซ่อม 0 ช่อง |
| **confusionMap** | ยัด option ปลอมให้ติดธง | แยก 2 ตาราง — `confusionMap` (ยืนยันจากรูปจริง ตัวเลือกเดียว = ซ่อม) · `shapeOnlyConfusionMap` (เดาจากรูปทรง = **ติดธงเสมอ**) |
| **`resolveSubjectCode`** | ต่อเข้า pipeline | ลบทิ้ง เรียก `classifySubjectCode` ตรงๆ เพราะต้องแยก `.alreadyValid` จาก `.repaired` · จุดตัดสินยังมีจุดเดียว |

### X1 · E3 "นับเสียง ว×2 vs ส×1" — ใช้ไม่ได้ ต้องผูกครูแทน

ข้อเสนอเดิม: ให้ ledger รับ `.repaired` **แล้วเปลี่ยนเป็นนับเสียงข้างมาก**

ครึ่งแรกถูก ครึ่งหลังผิด — เสียงข้างมากคือสิ่งที่ §1.2 ตัดทิ้งไปแล้วเพราะ tail ใช้ร่วมกันหลายวิชา
ถ้าเปิดกลับมา ม.5/9 จะพังทันที (tail `32101` = 6 วิชา, tail `32201` = 3 วิชา)

**ทางที่ถูก: รับ `.repaired` เข้ามาเป็นหลักฐาน แต่ยังเอกฉันท์ แล้วให้กุญแจ "ครู + tail" เป็นตัวตัด**

```
tail 30202 ทั้งใบ  →  {ว, ว, ส}   ไม่เอกฉันท์ → sheet-wide งดออกเสียง  ✓ ปลอดภัย
ครูปิยดา + 30202  →  {ว, ว}       เอกฉันท์   → #38 #60 ได้ ว30202      ✓ แก้ได้จริง
ครูคนอื่น + 30202 →  {ส}          ไม่ถูกแตะ                             ✓ ไม่ลาม
```

ได้ผลลัพธ์ที่ E3 ต้องการ โดยไม่ต้องเปิดประตูที่ปิดไปแล้ว
`canonicalTeacherNames` รวม `ครูปิยลา`/`ครูปิยตา` เข้าหา `ครูปิยดา` ให้อยู่แล้ว

> ยังต้องกันไก่กับไข่: หลักฐานที่รับเพิ่มต้องเป็น `.repaired` **ที่ไม่กำกวม**เท่านั้น
> (`.needsReview` / `.ambiguous` ห้ามเข้า ledger เด็ดขาด)

### X2 · E4 "`3` → `ว` ซ่อมได้เลย" — ขัดกับข้อมูล ม.5/9

`confusionMap` ปัจจุบันมี `"3": ["ส"]` ซึ่งมาจากใบ ม.5/9 (ยืนยันแล้ว 1 ครั้ง)
ม.4/9 บอกว่า `330261` → `ว30261`

**`3` แมปได้ทั้ง ส และ ว → ต้องเป็น multi-option ติดธง ห้ามซ่อมอัตโนมัติ**
ถ้าทำตาม E4 ตรงๆ (`3`→`ว` ตัวเดียว) ม.5/9 จะถูกซ่อมผิดเงียบๆ

`7` → `ว` ยังไม่มีข้อมูลขัด ให้เป็นตัวเลือกเดียวได้

### X3 · E4 "`9→ค` `M→ท` `R→ค` ทำงานแล้ว" — คนละกลไก

ทั้งสามตัวนี้ **ไม่ได้อยู่ใน `confusionMap`** — ที่ผ่านได้เพราะ Vision เสนอ candidate ที่ถูกมาเอง
แล้ว `classifySubjectCode` หยิบตัวแรกที่ผ่านไวยากรณ์ (ขั้นที่ 1 ของ pipeline)

สำคัญตรงที่: มันจะทำงาน **เฉพาะตอนที่ Vision บังเอิญเสนอมา** ไม่ใช่ทุกครั้ง
→ ควรใส่ลง `confusionMap` จริงๆ ด้วย เพื่อให้ทำงานสม่ำเสมอ ไม่ใช่ปล่อยไว้แล้วคิดว่าแก้แล้ว

## 3. บั๊กที่วัดได้จากดัมป์ — เรียงตามความเสียหาย

### E1 ⛔ · `length >= 20` ตัดคาบโฮมรูมทิ้ง → ทั้งคอลัมน์หาย

`TableGridBuilder` — `timeRanges`:

```swift
guard length >= 20, length <= 180 else { return nil }
```

คาบโฮมรูมของโรงเรียนนี้คือ **`08.15-08.30` = 15 นาที** → ถูกตัดว่าเป็นขยะ

ไล่ตัวเลขจากดัมป์ ม.4/9:

| candidate | สมาชิก | เหตุ |
|---|---|---|
| `numericHeaderCandidate` | **7** | Vision อ่านเลข `0` `5` `6` `8` ไม่ออกเลย เหลือ 1,2,3,4,7,9,10 |
| `timeCandidate` | **10** | 11 ช่วง ลบ `08.15-08.30` ที่ถูก guard ตัด |

10 > 7 → `bestPositions` เลือกแถวเวลา → `fitAxis` ได้ `origin` = คอลัมน์ `08.30-09.20`, `count = 10`
→ โฮมรูม (x 0.145) คำนวณได้ index **−1** → `Axis.index(for:)` คืน nil → **ทิ้งทั้งคอลัมน์**

ตรงกับ output เป๊ะ: `จันทร์ ค0 08:30-09:20` และไม่มีโฮมรูมสักแถว

**แก้:** `length >= 10` — คาบโฮมรูม/เข้าแถว 10–20 นาทีเป็นเรื่องปกติ
`00.00-00.00` ยังถูกตัดเพราะ length = 0 ✓ ไม่เสียการกรองขยะ

> ค่าคงที่ตัวเดียว 1 บรรทัด แต่ทำทั้งคอลัมน์หาย — **แก้ก่อนอย่างอื่น**

### E2 ⛔ · `contentShift` พังกับช่อง 3 บรรทัด → ข้อมูลผิดแถวแบบเงียบ

**อันตรายที่สุดในเอกสารนี้** เพราะข้อมูลไม่หาย แต่ไปโผล่ผิดแถวโดยไม่มีธง

หลักฐานตรงจาก output ม.4/9:

```
จันทร์ ค0  831102 · ครูศิริรัตน์         ← ไม่มีห้อง
อังคาร ค0  831102 · ครูศิริรัตน์ · 236   ← "236" ตัวนี้คือห้องของจันทร์ (#27)
ศุกร์  ค2  … · 236                       ← ในกระดาษเป็น 238 · ได้ห้องของพฤหัสฯ (#77) มา
```

**กลไก** — แกนวัน pitch 0.1312, เนื้อหาในช่องกิน 0.072:

```
รหัส  residual   0
ครู   residual  −0.035
ห้อง  residual  −0.072  →  |−0.072 / −0.1312| = 0.55 > 0.5  →  ปัดไป index ถัดไป
                            residual พลิกเป็น +0.059
```

`contentShift` คำนวณ index จากแกน**ที่ยังไม่ได้ shift** (ไก่กับไข่) → บรรทัดห้องถูกจัดเข้าแถวถัดไป
median ของ residual ทั้งหมด (≈0 · −0.035 · +0.059 จำนวนใกล้เคียงกัน) → **ตกที่ 0** → `shift = 0` → ไม่แก้อะไรเลย

ค่าที่ถูกคือ **−0.036** (กึ่งกลางของเนื้อหาจริง)

> **หมายเหตุที่ต้องรู้:** บั๊กนี้กระทบ ม.5/9 ด้วย ไม่ใช่แค่ ม.4/9
> ใบนั้น pitch 0.084 · offset ห้อง −0.047 → 0.047/0.084 = **0.56 > 0.5** ปัดผิดเหมือนกัน
> ตอนประเมินด้วยมือรอบแรกคำนวณจุดนี้พลาด — **ห้ามเชื่อตัวเลข "ถูกเป๊ะ" ของ ม.5/9 จนกว่าจะยิงซ้ำหลังแก้ E2**

**แก้:** เลิกใช้ median ของ residual ที่คำนวณจากแกนตัวเอง
ให้จับเนื้อหาที่อยู่ในระยะ ±1 step จาก anchor แต่ละแถว แล้วตั้ง origin เป็น **กึ่งกลางระหว่าง min กับ max ของเนื้อหานั้น**

### D1 ⛔ · `periodNumber` ใช้ index ของแกนเป็นเลขคาบ → เลื่อนทั้งตาราง

```swift
periodNumber: reading.period    // ScheduleOCRParser
```

`OCRTableGrid` มี `dayNumbers: [Int]` ที่ทำถูกแล้ว (แมปจากชื่อวันที่อ่านได้ แล้วเติมที่เหลือด้วยการนับ)
**แต่แกนคาบไม่มีของแบบเดียวกัน**

อาการ: ม.4/9 output เขียน `ค0 08:30-09:20` แต่ในกระดาษช่องนั้นคือ **คาบ 1** (เดิม E6)

**แก้:** เพิ่ม `periodNumbers: [Int?]` ทำแบบเดียวกับ `weekdays(for:dayBoxes:daysAreRows:)`
- `numericHeaderCandidate` ตอนนี้ทิ้ง**ค่า**ของตัวเลข เก็บแต่ fraction → ต้องเก็บค่าไว้ด้วย
- แมปเลขที่อ่านได้ลง index → หา offset ที่พบบ่อยสุด → เติมช่องที่เหลือด้วยการนับ
- คอลัมน์ที่ไม่มีเลขพิมพ์ (โฮมรูม/พัก) → `nil`

### E5 · Vision อ่านเลขคาบโดดๆ ไม่ออก — ยืนยันว่าห้ามพึ่งแถวเลขอย่างเดียว

→ ตอกย้ำ **D1** (ต้องเติมด้วยการนับ) และ **D2** (ต้องรวมหลักฐาน)

### D2 · `bestPositions` เลือกกลุ่มเดียว ไม่รวมหลักฐาน

วนดู candidate แล้วเก็บ**กลุ่มที่สมาชิกเยอะสุดกลุ่มเดียว** — แต่แถวเลขคาบกับแถวเวลาเป็นหลักฐานของ
**แกนเดียวกัน คนละแหล่ง** ควรรวมกันก่อนแล้วค่อย cluster

ม.4/9 ถ้ารวม: เลข 7 ∪ เวลา 11 (หลังแก้ E1) → ครบ 11 คอลัมน์แม้เลขจะหาย 4 ตัว
เพิ่มเติม: ตอนเสมอกันใช้ `>` เฉยๆ → ยึดกลุ่มแรกในอาร์เรย์โดยไม่มีเหตุผลรองรับ

### D3 · แกนคาบไม่มี logic ขยายเมื่อมีเนื้อหาตกนอกกรอบ

แกนวันมี (`headerIndices` / `lowestDay`) แต่แกนคาบไม่มี
ถ้ามี content box ตกที่ index −1 อย่างสม่ำเสมอ (โฮมรูม 5 ใบเรียงเป็นคอลัมน์) แปลว่าแกนสั้นไป
→ ขยาย `origin` ไป 1 ช่อง แทนที่จะทิ้งข้อมูล

**นี่คือทางแก้ที่ครอบคลุมที่สุดของอาการ "โฮมรูมหาย"** เพราะไม่พึ่งว่าโรงเรียนพิมพ์เลขหรือเวลากำกับไหม
(E1 แก้เคสเฉพาะหน้า · D3 แก้ที่ราก)

### E4 · `confusionMap` ยังขาดตัวที่เจอบ่อย

## 4. โครงสร้างที่ ม.1/1 มี แต่โค้ดยังรับไม่ได้เลย

### D8 · ชื่อครูภาษาอังกฤษ — กฎปัจจุบันผิด

ม.1/1 มี `T.Kathleen` และ `ครู Kathleen Baldazan Bandao`

|---|---|
| `T.Kathleen` ไม่ขึ้นต้น `ครู`/`คร` → คืน `nil` | ตกไป freeText → **กลายเป็นชื่อวิชา** |
| `ครู Kathleen…` มีอักษรละติน → `needsReview = true` | **ติดธงทั้งที่อ่านถูก** |

> กฎ **"ชื่อครูต้องไม่มีอักษรละติน" ผิด — ยกเลิก**
> เปลี่ยนเป็น: ละตินล้วนที่ขึ้นต้น `T.` / `Teacher` / `Mr.` / `Ms.` = ชื่อครูที่ถูกต้อง
> ธง `needsReview` ให้เหลือเฉพาะเคส "เหลือตัวเดียวหลังตัดคำนำหน้า" (`ครูA`)

| `นาฏศิลป2` (ม.4/9) | ✗ |

ที่ไม่ผ่านจะตกไป freeText แล้วถูกต่อเป็นชื่อวิชา

### D4 · เวลาที่ขึ้นบรรทัดใหม่

ม.1/1 พิมพ์ `08.00-` / `08.30 น.` เป็นสองกล่องคนละบรรทัด แต่คอลัมน์เดียวกัน
`timeRangeRegex` ต้องการหัวท้ายครบในสตริงเดียว → แมตช์ไม่ติด
→ ก่อนหาแกน ให้ลองต่อกล่องที่ x ซ้อนกันและ y ติดกันเข้าด้วยกันก่อน แล้วค่อยยิง regex

### D7 · ช่อง merge แนวนอน (คาบคู่) — เสี่ยงกว่าที่คิด

ม.1/1 มีเยอะ: จันทร์ คาบ6–7 · อังคาร คาบ2–3 · พุธ คาบ1–2 · ศุกร์ คาบ2–3 · ศุกร์ คาบ5–6

`split()` ทำงานเมื่อ `box.width > 1.5 × pitch` แต่ช่องคาบคู่มีข้อความ**สั้นและจัดกึ่งกลาง**
(`ว21101` โทเคนเดียว) → กล่องไม่กว้าง → ไม่ split
→ จุดศูนย์กลางตกบนเส้นแบ่งคอลัมน์พอดี แล้วปัดเข้าช่องใดช่องหนึ่ง อีกช่องว่าง
**แย่กว่านั้น:** บรรทัดรหัส/ครู/ห้อง ยาวไม่เท่ากัน อาจปัดคนละทาง → ช่องเดียวถูกฉีกเป็นสองช่อง

→ ต้องตัดสินจากความกว้างของ**ช่องในตาราง** ไม่ใช่ความกว้างของกล่องข้อความ

### D6 · ช่อง merge แนวตั้ง

ม.1/1: `โฮมรูม` ช่องหนึ่งคร่อม จันทร์+อังคาร อีกช่องคร่อม พฤหัส+ศุกร์ · `พักกลางวัน` คร่อมทั้ง 5 วัน
โมเดลเป็น `cells[day][period]` และวางชิ้นส่วนตาม**จุดศูนย์กลาง**เท่านั้น → ตกแถวกลางแถวเดียว แถวอื่นว่าง

### D5 · ข้อความแนวตั้ง (หมุน 90°)

ม.1/1 พิมพ์ `โฮมรูม` และ `พักกลางวัน` แนวตั้ง

- Vision ตั้งค่าปกติอ่านข้อความหมุนไม่ได้ → หายไปเฉยๆ
- ต่อให้อ่านได้ bounding box จะสูงแคบ ทำให้ `split()` และ `tokens()` ซึ่งสมมติว่าข้อความไหลตามแกน x คำนวณผิดหมด
- **กระทบหนัก:** `repeatedTextCandidates` พึ่ง "คำที่ซ้ำหนึ่งครั้งต่อแถว" ซึ่งก็คือ `โฮมรูม` — โรงเรียนนี้ anchor ตัวนั้นใช้ไม่ได้เลย

ทางเลือก: ยิง Vision รอบสองบนภาพที่หมุน 90° แล้วรวมผล · หรือยอมรับแล้วพึ่ง anchor อื่น (ชื่อวัน + เลขคาบ)
